# 立项与发布文件

把市场数据、竞品、产品资料和利润测算整理成给同事汇报用的 Word / PDF。两种文件共用同一套数据和竞品表，结构不同：

| | 立项文件 | 发布文件 |
|---|---|---|
| 时点 | 打样前，决定做不做 | 产品定型，准备上架 |
| 结构 | `references/立项结构.md` | `references/发布结构.md` |
| 销量预估 | **不写** | 写，按"直接竞对"格式 |
| 规格 | 一张简表 | 按尺寸写全：结构功能、材质、尺寸重量包装、出厂价 |
| 利润 | "产品落地价格（打样前）"一张表 | 各平台按尺寸的售价表 + 每个 SKU 利润表 |

## 流程

1. **收资料，缺了再问**。先读用户给的立项文档、利润测算（截图 / xlsx / JSON）、渲染图、规格、调研。需要的信息清单见 `references/输入清单.md`；只问会改变结论的缺项（我们的售价、材质、尺寸、对标渠道），不要让用户重复已给的内容。以前的同类文件（用户提供的历史立项 / 发布）是最高优先级的格式参考，先读。
2. **定口径**。确认范围（品类、尺寸段、整装 / 拆装、形态）、月份窗口（默认最近 3 个月月均）、各渠道销量来源。口径写进文中数据来源注释。见 `references/数据口径.md`。
3. **找竞品，分层级**。每个渠道按 `references/竞品层级.md` 分出"同价位头部 / 低价走量款 / 同规格贵价款 / 同元素款 / 价格最接近款"，每个渠道至少覆盖两个层级，不能只放头部。
4. **做交叉看板图**。维度不固定：先把这份文件的机会点写成"在 A 上，B 是空的 / 少的 / 贵的，我们补上"，A、B 就是两条轴（价格 × 台面、尺寸 × 台面、尺寸 × 元素、台面 × 柜体……），判断步骤和例子见 `references/看板图.md`。用 `scripts/cross_matrix.py` 出图，**必须用黄色行 + 黄框标出我们的位置**。每个渠道一张，放在该渠道小节的要点后、竞品表前；出图后自检"只看这张图能不能讲清机会点"。
5. **写正文**。按对应结构写，遵守 `references/写作规范.md`（正式、可汇报、无 AI 腔、每个判断带数字）。竞品表用 `scripts/docx_kit.py` 的 `comp_table`，"和我们比"一栏按**我们的促销价**算差价。
6. **生成并检查**。python-docx 出 Word → LibreOffice 转 PDF → 逐页转图看一遍（表格宽度、图片、空白页、乱码方框）。见 `scripts/docx_kit.py` 文件头说明。
7. **改稿**。用户说"只改这里 / 在对话里给表"时，在对话里用 Markdown 表给改动，不重出 Word；用户确认后再统一出文件。

## 必须做到

- 竞品对比必须"同尺寸、同规格"地比，并且覆盖贵价同规格款，不能只拿低价头部比（见 `references/竞品层级.md`）。
- 每张交叉看板图都有：月销、款数、单款月销、加权评分；价格不是坐标轴时加"加权均价"；有"我们"所在的黄行和黄框；图下写口径和数据来源。
- 数字可追溯：每个数字能回到数据表或用户材料；推断写明依据（如"销量按评论推算""按排名档位估算"）。
- 写之前核对一句话结论是否和数据冲突（例："Amazon 没有 $300 以下 24″ 整装"要先查，有就写"很少，X 个 ASIN，合计每月约 Y 件"）。
- 场景图、渲染图由用户提供；需要场景图时只给提示词，不自己生成图片。

## 文件

- `references/立项结构.md`、`references/发布结构.md`：章节结构与每节要写什么。
- `references/竞品层级.md`：竞品分层、每个竞品要收集的字段、"和我们比"的写法、差评分析。
- `references/看板图.md`：交叉看板图怎么选维度、怎么读、放在哪；其他常用图。
- `references/数据口径.md`：各渠道销量来源与推算、利润率口径、常见坑。
- `references/写作规范.md`：措辞、格式、改稿习惯。
- `references/输入清单.md`：开工前要拿到的资料。
- `scripts/cross_matrix.py`：交叉看板图（HTML + PNG），支持任意两个维度、价格分箱、我们的位置。
- `scripts/docx_kit.py`：Word 排版工具（表格定宽、图片单元格、超链接、提示框、竞品表）。
