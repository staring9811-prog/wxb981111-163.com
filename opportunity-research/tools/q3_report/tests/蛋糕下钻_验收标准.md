# 蛋糕下钻 · 验收标准（按角色）

目的：老板、产品开发、运营各自打开蛋糕下钻，能在很少的点击内回答自己最关心的问题，并且不会误读。
A 类由脚本自动检查（页面上有没有、数对不对）；B 类由不知道答案的独立评审按角色实际操作后打分（能不能看懂、找不找得到）。

## 通用（所有角色）

| 编号 | 检查项 | 类 |
|---|---|---|
| G1 | 表格标题写出完整路径（渠道 · 第一层 › 第二层 · 按「X」分），以及这块蛋糕的月销和占全部比例 | A |
| G2 | 表格同时有「占本层」「占全部」两列；第一层两列相等 | A |
| G3 | 大蛋糕 = 本渠道（含当前筛选）同一层级所有组合按月销从大到小排、合计占一半销量的那些（不含未识别），图例写明维度；细分龙头（原名小蛋糕）= 占本层 ≥ 20% 且占本渠道 ≥ 0.3%（防止几十件的小格被标成细分龙头）；第一层只标大蛋糕；标签旁有图例说明，悬停有「主战场 / 大而分散 / 细分龙头」解释 | A |
| G4 | 进入：点饼块 / 表格行 / 热力图格子；退出：返回按钮、面包屑、饼图中心、Esc、浏览器后退，均可用 | A |
| G5 | 展开价格段时，父行与子行一眼可分（底色、缩进、连线） | B |
| G6 | 没有让人误读的数字或说法（评审列出所有"看不懂 / 以为是 X 其实是 Y"的地方，严重的为不通过）；页面不出现"全市场"，统一说"本渠道"；「未标」显示为「未识别」 | A + B |
| G7 | 涨跌为正但 10 月比 9 月跌 ≥ 25% 时，涨跌旁提示「10月回落」 | B |

## 老板：市场格局与我们的覆盖（第一屏 + 最多 1 次点击）

| 编号 | 要回答的问题 | 类 |
|---|---|---|
| B1 | 市场主战场是哪几块？（第一层大蛋糕 + 主要在涨 / 在跌的块） | A + B |
| B2 | 我们在主战场覆盖了多少（看点卡写「主力 N 块进了 M 块，共 X SPU，占我们这一层的 Y%」），哪块大蛋糕我们没有布局？ | A + B |
| B3 | 30 秒内能说出一句结论（例："夏克式、农场风是最大的两块，我们各只有 1 个 SPU；竖棱在涨 24%，我们布局最多"） | B |

## 产品开发：找下一个要开发的品（最多 3 次点击）

| 编号 | 要回答的问题 | 类 |
|---|---|---|
| P1 | 找出至少一个「机会」格子：我们未布局 + 在涨 ≥ 15% + 大 / 细分龙头或占本渠道 ≥ 1%（元素 · 形态 · 尺寸）；本层没有时看点卡列出下一层的机会格，热力图用绿色「机」角标 | A + B |
| P2 | 这个格子的价格段分布（低 / 中 / 高价各卖多少、哪段在涨；区间写成 $a–b / $c 以上，不重叠；有销量的商品少于 6 款不分段）、头部集中度、低分占比、评价门槛 | A + B |
| P3 | 能看到这个格子的竞品清单（图、标题、价格、评分、月销），可点开商品页 | A + B |

## 运营：我们已有产品的位置（最多 3 次点击）

| 编号 | 要回答的问题 | 类 |
|---|---|---|
| O1 | 我们某个 SPU（如「悬浮式 reeded 岗石」）在各尺寸的格子里：市场月销、涨跌、我们价差、落在哪个价格段；点「我们」的产品标签能直接跳到它所在格子并展开价格段 | A + B |
| O2 | 找出需要调整的块，标签分三种：在跌（涨跌 ≤ −15%）、太小（占本渠道 < 1% 且没在涨）、布局偏重（我们这层 ≥ 2 款且 ≥ 20% 的产品在这块，且是这块市场占比的 2 倍以上）；看点卡里每个标签后直接写依据 | A + B |
| O3 | 能上传 / 修改我们的产品清单，修改后结果立即更新 | A |

| G8 | 标签口径在「这一层看点」底部一次写全（大蛋糕、细分龙头、主战场、机会、在跌、太小、布局偏重、10月回落），与悬停、表头图例一致 | B |

| G9 | 版面：顶部一句话结论条；饼图与指标卡、我们的产品同一行；看点分「主战场 / 我们 / 机会 / 需调整」四张卡、每条一行；最后一层「开发候选」分概况 / 价格段小表 / 建议三栏；标签口径与页脚口径默认收起 | B |

## 通过线
- A 类全部通过。
- B 类：三个角色的任务全部能完成，且回答的关键数字与页面真实数值一致；每个角色的清晰度评分 ≥ 4 / 5；没有严重误读。
