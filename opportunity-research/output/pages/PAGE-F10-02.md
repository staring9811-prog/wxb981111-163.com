## 2. 页面概述

### 2.1 一句话定位

一次提交一条立项记录：要么记下本月的立项决定，要么补录系统启用前已在研的立项。

### 2.2 存在理由

1. **决定要和当时的快照绑在一起**：日后对账要对照"当时系统怎么排、锦囊怎么说"，所以记录时自动带入当前快照（AC-F10-02）。
2. **在研项目要能纳入对账**：系统启用前立的项没有快照，需要补录立项日期和关联细分（AC-F10-03）。
3. **记录不能事后修改**：保存前必须看清"保存后不可改"（DEC-007）。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 快 | 从排序行打开时关联细分与快照已带入，只需选决定、写理由 |
| 不丢上下文 | 记录时可见该细分在本月排序中的排名、区间与锦囊 |
| 不误存 | 必填项缺失不能保存；有未保存内容时关闭会提醒 |

### 2.4 不做什么

- **不编辑已保存的记录**：录错只能从立项记录行"更正"，追加新记录（DEC-007）。
- **不录入上架数据**：在 PAGE-F10-06 录入。
- **不改快照或锦囊**：对应快照只读带入。

## 3. 用户与场景

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 产品经理 wen |
| 使用时机 | 月度立项评审后；首跑补录；发现录错时更正 |

- **场景 A：从排序记录决定**：在本月排序第 1 名"30–48″ · 落地式 · $500–900"上点"记录立项决定"，选"立项"，写理由，保存。
- **场景 B：补录在研立项**：首跑时补录"30″ 悬浮式双抽柜（ZR-2026-07）"，立项日期 2026-07-02，当时依据"2026 年初人工研究报告"。
- **场景 C：更正**：D-0003 的关联细分误填，从立项记录点"更正"，带入原内容后改正细分并保存，生成 D-0004。

## 4. 信息架构

### 4.1 区域划分

1. 弹窗头：标题"记录立项决定"，副标题"写入台账 · 立项记录 · 2027-05 月更"，关闭。
2. 模式标签：记录决定 / 补录在研立项。
3. 不可修改提示（每种模式顶部）。
4. 表单。
5. 弹窗脚：操作人与时间说明、"取消"、"保存记录"。

### 4.2 区域内容

**记录决定**

| 字段 | 内容 | 规则 |
| :--- | :--- | :--- |
| 关联细分 | 下拉，列出品类配置 v2 的 18 个细分 | 必填；从排序行打开时已带入，可改选 |
| 这个细分在本月排序中 | 本月排名与有效细分数、得分、预期命中率区间条与样本量、锦囊动作、规则编号与状态 | 只读；随所选细分变化，随快照一起记录 |
| 决定 | 立项 / 不立项（单选） | 必填 |
| 立项日期 | 默认当天 | 决定为"立项"时显示；格式 YYYY-MM-DD，不晚于今天 |
| 立项名称 | 文本 | 选填；不填时以关联细分作为名称 |
| 对应快照 | 当前最新快照，如"2027-05 · 第 1 版（判定卡 v4）" | 自动带入，只读 |
| 理由 | 多行文本 | 必填 |

**补录在研立项**

| 字段 | 内容 | 规则 |
| :--- | :--- | :--- |
| 立项名称 | 文本 | 必填 |
| 立项日期 | YYYY-MM-DD | 必填，不晚于今天 |
| 关联细分 | 下拉 | 必填 |
| 当时的研究依据 | 多行文本 | 选填；日后对账时与结果并列展示 |

补录记录的来源自动为"补录"，没有对应快照。

**更正**：从立项记录行"更正"打开时，标题为"更正立项记录"，副标题注明"更正 D-xxxx"；按原记录的模式打开并带入原内容，对应快照沿用原记录的快照。

## 6. 交互流程

### 6.1 加载与初始化

- 从本月排序行打开：默认"记录决定"，关联细分为该行细分，立项日期为当天。
- 从立项记录"记录决定"打开：关联细分为空，选中后显示排序上下文。
- 从立项记录"补录在研立项"打开：默认"补录在研立项"。
- 从立项记录"更正"打开：带入原记录内容。

### 6.2 核心操作流程

```
打开弹窗
  ├─ 切换模式标签 → 显示对应表单（已填内容各自保留）
  ├─ 改选关联细分 → 排序上下文换成该细分在本月排序中的数据
  ├─ 选"不立项" → 隐藏立项日期
  └─ 点"保存记录"
       ├─ 必填缺失 → 字段下方提示，不保存
       └─ 通过 → 生成新编号（如 D-0007），写入操作人与时间 → 关闭弹窗
            → 回到来源页，轻提示"已记录 D-0007"；更正时原记录同时标"已更正"
点"取消"、关闭或按 Esc
  ├─ 无改动 → 直接关闭，回到来源页
  └─ 有改动 → 提示"有未保存的内容，确定离开？"
```

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 记录决定（已带入） | 从排序行打开 | 细分与排序上下文已显示 |
| 记录决定（待选择） | 从立项记录打开 | 细分为空，上下文区提示"选择细分后显示它在本月排序中的位置" |
| 补录 | 选补录标签 | 补录表单 |
| 更正 | 从"更正"打开 | 标题"更正立项记录"，带入原内容 |
| 没有快照 | 本品类还没生成过排序 | "记录决定"不可用，提示"还没有快照，请先生成本月排序；系统启用前的立项请用补录" |
| 保存中 | 点保存后 | 按钮显示"保存中…"，不能重复提交 |
| 校验失败 | 必填缺失或格式错误 | 字段下方显示错误，焦点移到第一个错误字段 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 保存后本月又重算 | 记录仍对应保存时的快照版本；对账按记录的快照展示当时排名 |
| 同一细分多次决定 | 允许，每次一条记录，各自对应保存时的快照 |
| 样本不足的细分 | 可以记录；排序上下文显示"样本不足"和较宽的区间 |
| 补录日期晚于今天 | 不允许保存 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| 对应快照 | 保存时最新的快照（月份 + 第 n 版），记录后不随重算变化（AC-F10-02） |
| 来源 | 记录 / 补录 / 更正，系统按打开方式自动写入 |
| 操作人与时间 | 取本机配置的操作人（wen）和保存时刻，不可编辑 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 关联细分 | 提交时 | 必选 | "请选择关联细分" |
| 决定 | 提交时 | 必选 | "请选择立项或不立项" |
| 理由 | 失焦、提交时 | 非空 | "请写下理由，日后对账要看当时为什么这样决定" |
| 立项日期 | 失焦、提交时 | YYYY-MM-DD 有效日期，不晚于今天 | "请按 2027-05-08 的格式填写，且不晚于今天" |
| 补录必填项 | 提交时 | 立项名称、立项日期、关联细分都已填写 | 对应字段下方提示"必填" |

### 8.3 特殊业务规则

- **不可修改**（DEC-007）：保存后不提供修改；更正生成新记录，原记录标"已更正"并互链。
- **编号**：按保存顺序递增，不复用。

## 10. 数据需求

### 10.1 页面需要的数据

| 数据 | 来源 | 用途 |

### 10.2 页面提交的数据

| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| 决定、关联细分、理由、立项日期、立项名称、对应快照 | 记录决定模式保存 | 新增立项记录（来源"记录"） |

- 不提交上架数据、不修改快照与锦囊。
