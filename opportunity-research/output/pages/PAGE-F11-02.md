## 2. 页面概述

### 2.1 一句话定位

把一条规则写成回测能直接执行的条件，每次修改都留下版本、理由和操作人。

### 2.2 存在理由

1. **条件要能被回测执行**（DEC-013）：自由文字写的经验无法进入回测，规则就永远停在"未验证经验"。
2. **修改要有交代**（AC-F11-04）：规则会进入立项锦囊，每次修改都要保留旧版本、理由、操作人和时间。
3. **防止改过的规则沿用旧证据**（AC-F11-05）：条件或动作变了，原来的回测和对账结论不再适用，新版本必须回到"未验证经验"。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 可执行 | 100% 的条件由"维度或信号 + 比较 + 值"组成，不接受自由文字条件 |
| 可追溯 | 每个版本都能看到条件、动作、理由、状态、操作人、时间和与上一版的差异 |
| 不误导 | 改了条件或动作，保存前一定出现状态重置提示 |

### 2.4 不做什么

- **不手动设置状态**：状态只由新增、修改、回测和对账决定，抽屉里没有状态选择。
- **不删除规则或版本**：版本只追加（DEC-014）。
- **不在抽屉里运行回测**：保存后的版本在下一次回测中按新条件执行。
- **不写自由文字条件**：补充说明写在理由里。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 产品经理 wen |
| 使用时机 | 评审会后录入经验；发现规则口径需要调整时修改；回看规则的变更历史 |
| 使用设备 | Windows，宽 1366–1920；抽屉宽 600 |

### 3.2 核心使用场景

- **场景 A：修改规则（主场景）**
  - 例：R-016 当前为 v2。wen 想把结构类痛点阈值从 10% 调到 12%，改值后出现状态重置提示，填写理由后保存为 v3。
- **场景 B：新增经验规则**
  - 例：评审会提出"安装方式为壁挂、价格带 $500–900 先观察"，新增后保存为 R-019 v1，状态未验证经验（AC-F11-01）。
- **场景 C：回看变更**
  - 例：查看 R-016 的 v1（回测 BT-0024 生成，历史观察）到 v2（wen 把需求在涨的阈值从 +15% 提高到 +20%，状态重置）改了什么。

## 4. 信息架构

### 4.1 区域划分

1. 抽屉头：标题、当前版本与状态、来源、关闭。
2. 条件区：条件行列表、"添加条件"。
3. 动作区。
4. 状态重置提示（改动条件或动作后出现）。
5. 理由。
6. 版本历史。
7. 抽屉脚：未保存提示、取消、保存。

### 4.2 区域内容

**抽屉头**
- 编辑：标题"编辑规则 R-016"；副标题"当前 v2 · 未验证经验 · 由回测 BT-0024 生成，v2 由 wen 于 2027-04-02 修改"。
- 新增：标题"新增经验规则"；副标题"保存后为新规则 v1，状态为未验证经验"。

**条件区**
- 每条条件一行："当 / 且" + 维度或信号 + 比较 + 值 + 删除。
- 多条条件之间为"且"，全部满足才触发；区块右侧注明"全部满足时触发 · 回测按同一口径执行"。
- 底部"添加条件"，并说明"维度取值来自品类配置 v2 的分档；信号按第 T 月只用早于 T 月数据的口径计算"。

**动作区**
- 三选一：立项候选 / 观察 / 放弃（必选）。
- 常驻说明："条件或动作一改，保存后的新版本就是'未验证经验'，要重新经过回测才能回到'历史观察'。"

**状态重置提示**（改动条件或动作后出现，AC-F11-05）
- 标题："保存后状态将变为未验证经验"。
- 说明："你改了条件或动作。保存后生成 v3，状态为'未验证经验'；v2 保留原状态，可在版本历史里回看。"

**理由**（必填）
- 编辑时标签为"修改理由"，新增时为"理由"；提示"每次保存都要填写，随版本保留，连同操作人和时间一起记录"。

**版本历史**（新的在上）
- 每个版本：版本号、状态、时间、操作人（wen 或"系统 · 回测编号"）、理由或生成依据。
- 与上一版的对比：只列有变化的项，旧值划线、新值高亮；末尾说明未改的部分。
- R-016 示例：
  - v2 · 当前 · 未验证经验 · 2027-04-02 14:20 · wen · 理由："把需求在涨的阈值从 +15% 提高到 +20%——悬浮式搜索量受季节影响大，+15% 在旺季前后容易误报"。对比：条件 1 "需求在涨 ≥ +15%" → "需求在涨 ≥ +20%"；状态 历史观察 → 未验证经验；条件 2、条件 3 和动作未改。
  - v1 · 历史观察 · 2027-03-05 15:38 · 系统 · 由回测 BT-0024 生成（定规则批次 2025-04–2026-03，检验批次 2026-04–2026-09，样本 41）。条件："当 需求在涨 ≥ +15% 且 形态 = 悬浮式 且 结构类痛点占比 ≥ 10% → 观察"。

## 5. 界面内容

### 5.1 元素清单

| 元素 | 内容 / 文案 | 数据来源 | 显示条件 |
| :--- | :--- | :--- | :--- |
| 维度或信号 | 信号：需求在涨（同比，窗口按品类配置）、新品进得去、结构类痛点占比、高销低评占比。候选信号：单位 ASIN 贡献、属性溢价、属性趋势、低分高销。维度与属性：宽度档、形态、价格带、安装方式、元素、台面形态、柜体材质、台面材质、台盆材质、颜色、盆数 | 品类配置当前版本、信号清单 | 每条条件 |
| 比较 | 信号：≥、>、≤、<；维度：=、≠ | — | 每条条件 |
| 值 | 信号填数值（如"+15%"、"40 件"、"+1 个百分点"）；维度从该维度的分档或取值中选（如"悬浮式"） | 品类配置分档 | 每条条件 |
| 删除条件 | 叉号按钮 | — | 只剩一条条件时不可用 |
| 添加条件 | 新增一行空条件，焦点落在"维度或信号" | — | 始终 |
| 动作 | 立项候选（旗帜）/ 观察（眼睛）/ 放弃（禁止） | 规则当前版本 | 始终 |
| 状态重置提示 | 见 4.2 | — | 条件或动作与当前版本不同 |
| 未保存提示 | "有未保存的修改" | — | 有任何修改 |
| 保存按钮 | 编辑："保存为 v3"（当前版本号 + 1）；新增："保存" | — | 始终 |

### 5.2 辅助信息

- 抽屉打开时，背景策略库中对应的行高亮。
- 候选信号在下拉中分组显示，提醒它们是待检验的现用指标。

## 6. 交互流程

### 6.1 加载与初始化

- **编辑**：载入当前版本的条件、动作；理由为空；加载全部版本历史。
- **新增**：一条空条件，动作未选，没有版本历史。
- **有本机草稿**：同一规则上次未保存的修改从草稿恢复，并显示"有未保存的修改"（蓝图 §5）。

### 6.2 核心操作流程

```
打开抽屉
  ├─ 改条件（改值、换维度或信号、增删条件行）或改动作
  │     → 出现"保存后状态将变为未验证经验"提示；底部显示"有未保存的修改"
  ├─ 只改理由
  │     → 不出现状态重置提示；保存后生成新版本，状态不变
  ├─ 点"保存为 v3"
  │     ├─ 条件不完整 / 动作未选 / 理由为空 → 在对应位置提示，不保存
  │     └─ 通过 → 生成新版本（版本号 + 1），记录理由、操作人、时间
  │              → 关闭抽屉，回到策略库，轻提示"已保存 R-016 v3 · 未验证经验"
  └─ 点取消、关闭、按 Esc 或点遮罩
        ├─ 没有修改 → 直接关闭
        └─ 有修改 → 离开提示；确认离开后修改保留为本机草稿
```

### 6.3 辅助操作

- 添加条件后，焦点自动落到新行的"维度或信号"。
- Esc 关闭抽屉（有修改时先提示）。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 查看 | 打开已有规则，未修改 | 显示当前版本与版本历史；无提示 |
| 编辑中 | 有任何修改 | 底部"有未保存的修改"；离开时提示 |
| 状态将重置 | 条件或动作与当前版本不同 | 状态重置提示常驻，直到恢复原样或保存 |
| 新增 | 从"新增经验规则"进入 | 空条件、动作未选、无版本历史；保存后状态为未验证经验（AC-F11-01） |
| 校验失败 | 保存时有必填项缺失或值不合法 | 字段下方显示错误，焦点移到第一个错误处 |
| 保存中 | 点击保存后 | 保存按钮不可重复点击 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 改了条件又改回原样 | 与当前版本完全一致时，状态重置提示消失 |
| 维度的值不在当前品类配置分档中 | 保存时提示"该分档不在品类配置 v2 中"，不保存 |
| 同一维度出现两条且互相矛盾（如 形态 = 落地式 且 形态 = 悬浮式） | 保存时提示条件互相矛盾，不保存 |
| 回测运行中保存规则 | 允许保存；本次回测仍用开始时的版本，新版本从下一次回测起执行 |
| 编辑已验证规则的条件 | 保存后新版本为未验证经验；已验证状态和对账依据保留在旧版本上（AC-F11-05） |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| 规则编号 | R-xxx，新增保存时由系统分配，之后不变 |
| 版本号 | 从 v1 起，每次保存 + 1 |
| 条件 | 一条或多条"维度或信号 + 比较 + 值"，之间为"且"（DEC-013） |
| 动作 | 立项候选 / 观察 / 放弃 |
| 理由 | 新增时为规则理由，修改时为修改理由；每个版本单独保存 |
| 状态 | 未验证经验 / 历史观察 / 已验证，由系统写入 |
| 操作人、时间 | 保存时自动记录（NFR-004） |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 条件数量 | 保存时 | 至少一条 | "至少需要一条条件" |
| 条件完整 | 离开输入框、保存时 | 每条的维度或信号、比较、值都已填写 | "这条条件还没填完" |
| 值格式 | 离开输入框 | 信号为数字，可带 %、+、−、"件"、"个百分点" | "请填数字，例如 +15%" |
| 动作 | 保存时 | 必选 | "请选择动作" |
| 理由 | 保存时 | 必填，不能只有空格 | "请写明理由" |

### 8.3 特殊业务规则

- **新增**：状态为未验证经验，来源为人工（AC-F11-01）。
- **修改**：生成新版本，保留历史版本、理由、操作人和时间（AC-F11-04）。
- **改条件或动作**：新版本状态为未验证经验，旧版本保留原状态（AC-F11-05）；只改理由时状态不变。
- **状态升级不在这里**：未验证经验 → 历史观察靠回测达标；历史观察 → 已验证靠台账对账——立项候选规则倍数 ≥ 2、放弃规则倍数 ≤ 0.5，观察规则只记录不升级（REQ-F11-01、AC-F11-03、AC-F11-06）。
- **回测执行**：维度条件筛选细分或新 SPU，信号条件按第 T 月只用早于 T 月的数据计算（AC-F06-03）；"需求在涨"按品类配置的窗口计算，规则不单独设窗口（DEC-030）。

## 9. 页面流转

```
PAGE-F11-01 策略库 ──新增 / 点击行──→ 规则编辑（本抽屉）
```

## 11. 验收标准

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 新增必填 | 条件、动作、理由任一缺失都不能保存；保存后状态为未验证经验（AC-F11-01） |
| F-02 | 修改生成新版本 | 每次保存版本号 + 1，版本历史保留旧版本、理由、操作人和时间（AC-F11-04） |
| F-03 | 状态重置提示 | 改了条件或动作，保存前出现"保存后状态将变为未验证经验"（AC-F11-05） |
| F-04 | 状态重置结果 | 保存后新版本为未验证经验，旧版本状态不变（AC-F11-05） |
| F-05 | 结构化条件 | 条件只能由维度或信号、比较、值组成，可增删，多条为"且"（DEC-013） |
| F-06 | 前后对比 | 每个版本列出与上一版不同的项 |
| F-07 | 离开拦截 | 有未保存修改时关闭或离开出现提示 |
| U-01 | 焦点 | 添加条件后焦点落在新行；Esc 可关闭 |
