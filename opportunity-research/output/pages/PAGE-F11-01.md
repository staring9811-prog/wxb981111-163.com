## 2. 页面概述

### 2.1 一句话定位

把回测生成的规则和 wen 的经验规则放在一处，一眼看清每条规则验证到哪一步、凭什么。

### 2.2 存在理由

1. **经验要能被检验**：经验写成规则，才能进入回测和台账对账，一步步从"未验证经验"走到"已验证"（US-F11-01）。
2. **状态必须看得见**：立项锦囊可能引用尚未验证的经验规则（如 R-018）。不标清状态，经验就会被当成结论用。
3. **依据可追溯**：每条规则的当前状态来自哪次回测、哪个对账月份、谁在什么时候改的，都要查得到（AC-F11-03、NFR-003）。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 状态清楚 | 每条规则都显示三种状态之一，计数与筛选结果一致 |
| 依据可查 | 历史观察显示回测编号，已验证显示对账月份与倍数，未验证经验显示人工理由 |
| 一步到编辑 | 新增或修改都一次点击进入规则编辑 |

### 2.4 不做什么

- **不在本页改规则**：修改在 PAGE-F11-02 规则编辑中完成，并生成新版本。
- **不删除规则或版本**：规则只追加版本（DEC-014）；第一期不提供删除业务数据的功能。
- **不手动改状态**：状态只由新增、修改、回测、对账决定（REQ-F11-01）。
- **不显示锦囊的预期命中率区间**：在 PAGE-F08-02 立项锦囊查看。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 产品经理 wen（第一期唯一维护人，D-12 的第一期形态） |
| 使用时机 | 立项评审前核对锦囊引用的规则；评审会后录入新经验；月更对账后看哪些规则升级 |
| 使用设备 | Windows，宽 1366–1920 |

### 3.2 核心使用场景

- **场景 A：评审前核对**
  - 动作：筛"未验证经验"，确认锦囊里的 R-018 仍是人工经验，汇报时不把它当结论。
- **场景 B：录入经验**
  - 动作：评审会提出新判断，点"新增经验规则"写成结构化条件。
- **场景 C：看对账结果**
  - 动作：2027-05 对账后，看到 R-012 升为"已验证"，依据为 2026-11 快照、规则倍数 2.07×；R-015（观察）记录了 0.78×，状态不变。

## 4. 信息架构

### 4.1 区域划分

1. 页头：标题、一句说明、"新增经验规则"。
2. 状态计数：已验证 / 历史观察 / 未验证经验三张计数卡。
3. 筛选栏：状态、来源、搜索。
4. 规则表。
5. 页脚：当前判定卡锦囊引用的规则。

### 4.2 区域内容

**页头**
- 标题"策略库"。
- 副标题："规则有版本、有验证状态 · 任何修改都生成新版本 · 改了条件或动作的新版本回到'未验证经验'"。
- 主按钮"新增经验规则"，打开 PAGE-F11-02（新增模式）。

- 已验证 1 条："历史观察规则在台账对账中达到验证条件：立项候选规则倍数 ≥ 2，放弃 ≤ 0.5；观察规则只记录"（AC-F11-03、AC-F11-06）。
- 历史观察 8 条（含截面回测生成的 3 条，带"截面"标签，DEC-029）："由达标的回测生成，或人工规则进入回测并达标"（AC-F11-02）。

- 状态：全部 18 / 已验证 1 / 历史观察 8 / 未验证经验 9。

- 两组可组合；搜索支持规则编号、条件文字和理由。

**规则表**（默认按最近修改从新到旧）

| 列 | 内容 |
| :--- | :--- |
| 规则 | 规则编号与当前版本（如"R-012 · v3"）；下一行写来源："回测生成"、"人工新增"，人工改过的回测规则写"回测生成，v2 人工修改" |

## 6. 交互流程

### 6.1 加载与初始化

- 默认显示全部规则，按最近修改从新到旧，每页 50 条（第一期浴室柜 18 条，一页显示完）。
- 筛选条件只在本次浏览中保留，不影响别的页面。

### 6.2 核心操作流程

```
进入策略库
  ├─ 点"新增经验规则" → 规则编辑抽屉（PAGE-F11-02，新增模式）
  ├─ 点某一行 → 规则编辑抽屉（PAGE-F11-02，载入该规则当前版本与版本历史）
  ├─ 点状态 / 来源筛选 → 表格即时过滤，"当前显示 n 条"同步更新
  ├─ 点依据中的"回测 BT-0031" → 回测（PAGE-F07-01）
  ├─ 点依据中的"对账 2026-11 快照" → 到期对账（PAGE-F10-05）
  └─ 点倍数旁的小标签 → 浮层显示对账的分子、分母和预期区间
```

### 6.3 辅助操作

- "最近修改"表头可切换升序 / 降序。
- 搜索框按规则编号、条件文字、理由匹配。

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 已验证或历史观察的规则被改了条件或动作 | 表中显示新版本，状态为未验证经验；旧版本的状态保留在版本历史里（AC-F11-05） |
| 人工规则进入回测并达标 | 状态变为历史观察，来源仍记"人工"，依据显示该次回测 |
| 回测重新生成已有规则的新阈值 | 记为该规则的新版本，操作人"系统"，依据换成新的回测编号 |
| 锦囊引用的规则是未验证经验 | 本页照常显示其状态；锦囊页按状态显示（PAGE-F08-02），不在本页拦截 |

## 8. 业务规则与校验

- **三种状态**（REQ-F11-01）：
  - 未验证经验：人工新增（AC-F11-01），或修改条件、动作后的新版本（AC-F11-05）。
  - 历史观察：由结论为"达标"的回测生成（AC-F11-02），或人工规则进入回测并达标。
  - 已验证：历史观察规则在一次台账对账中达到验证条件——立项候选规则倍数 ≥ 2，或放弃规则倍数 ≤ 0.5——并记录对账月份与规则倍数（AC-F11-03）。
  - 观察规则：对账只记录规则倍数和对账月份，不改变状态（AC-F11-06）。
  - 规则倍数：对账快照中适用该规则的细分，其对应批次起量新 SPU 的实际命中率 ÷ 同批次全类目平均命中率（REQ-F11-01）。
- **状态流转**（PRD §4.2）：未验证经验 → 历史观察（进入回测并达标）→ 已验证（对账：立项候选 ≥ 2 倍，或放弃 ≤ 0.5 倍）；历史观察或已验证被改条件、动作 → 新版本回到未验证经验。
- **版本**：规则内容（条件、动作、理由）的每次修改，以及回测、对账引起的状态变化，都生成一个新版本；版本只追加，不覆盖（REQ-F11-01、DEC-014）。
- **来源**：指规则首个版本的产生方式（人工新增 / 回测生成），之后被人工修改，来源不变。
- **操作人**：人工操作记录操作人；回测、对账写入的版本记为"系统"，并注明回测编号或对账月份（NFR-004）。
