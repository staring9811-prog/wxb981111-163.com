## 2. 页面概述

### 2.1 一句话定位

让老板在一个地方拍板决策卡立项和策略库"已验证"申请，每个结论都留下审批人、时间、结论和意见。

### 2.2 存在理由

1. 拍板过去靠口头，事后说不清当时批的是哪个版本、附了什么条件。
2. 批准后卡片还会被改，数字会随新数据漂移，无法对账。
3. 批准后要手工去台账登记，容易漏。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 留痕 | 100% 的审批记录审批人、时间、结论、意见 |
| 锁定 | 批准后卡片 100% 变为只读版本 |
| 自动登记 | 批准即在台账新增一条，漏登为 0 |

### 2.4 不做什么（范围边界）

- **不在本页编辑卡片或条目内容**：审批者只能审批和留意见（AC-F15-03）。
- **不做会签、多级审批**：需求只有一个审批者结论。
- **不做消息推送**：待审批数显示在侧栏和工作台。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 审批者（老板）：审批、留意见；操作者（wen）：看审批状态与意见，不显示审批按钮；只读：无入口 |
| 人数 | 审批 1 人 |
| 技术熟练度 | 中 |
| 使用设备 | 办公电脑浏览器；评审会投屏 |

### 3.2 核心使用场景

**场景 A：评审会上批准一张决策卡（主场景）**
- 时机：评审会。
- 前置：wen 已在 PAGE-F21-02 提交审批。
- 动作：打开审批 → 待我审批里选"树脂一体 · 30″ 拆装 · 落地式" → 看摘要，必要时"看全文" → 选"批准"、写意见 → 提交 → 确认弹窗 → 卡片锁定，台账自动登记。

**场景 B：退回修改 / 驳回**
- 动作：选"退回修改"或"驳回"，意见必填 → 提交 → 卡片回到草稿（退回）或标"已驳回"。

**场景 C：审批策略库"已验证"申请**
- 动作：选策略库申请 → 看结论与申请依据 → 批准则条目改为"已验证"并生成新版本；驳回则保持原状态。

**场景 D：wen 查看结论**
- 动作：在"已处理"里看结论、意见和结果（锁定版本、台账编号）。

### 3.3 用户核心诉求

1. **一眼看懂**：不用翻全文也能看到分渠道结论、把握、做到概率、利润和停止条件。
2. **留痕**：附带条件写进意见。
3. **不出错**：提交前再确认一次。

## 4. 信息架构

### 4.1 区域划分

1. 页头
2. 标签：待我审批 / 已处理
3. 待我审批：类型筛选 + 列表（左）+ 审批详情（右）
4. 已处理：结论筛选 + 列表 + 分页

### 4.2 区域内容

**待我审批列表**：类型、对象（名称 + 一行摘要）、主渠道 · 版本、提交人、提交时间。

**审批详情（决策卡）**：卡片名、版本、提交人与时间、"看全文"；摘要（分渠道结论、市场把握与份额区间、做到概率原值 / 扣偏差、Amazon 单件利润）；停止条件；结论单选（批准 / 驳回 / 退回修改）；意见；"批准后"说明（锁定只读版本、自动登记台账）；提交审批结论。

**审批详情（策略库申请）**：条目名、编号、申请人与时间、"看条目"；状态变化（当前 → 已验证）；结论、申请依据、当前版本；结论单选；意见；批准 / 驳回后的结果说明；提交。

**已处理列表**：类型、对象（链接）、结论徽章、审批人、审批时间（可排序）、意见、结果（已锁定版本与台账编号 / 卡片状态 / 条目状态）。

## 5. 界面内容

### 5.1 元素清单

**侧栏待审批数**
- 内容：待我审批条数；显示条件：审批者，有待审批时。

**类型筛选**
- 选项：全部 / 决策卡立项 / 策略库改为已验证，带条数。

**结论单选**
- 选项：批准 / 驳回 / 退回修改；必选。

**意见**
- 驳回和退回修改时必填；批准时可选。

**"批准后"说明**
- 文案：卡片锁定为只读版本 v3，数字保存为批准时的快照；自动在预测台账登记（预计上架月）。
- 显示条件：选中"批准"且类型为决策卡。

**提交审批结论（主按钮）**
- 点击后打开确认弹窗：审批人、时间、结论、意见、批准后的影响；"确认提交"。

**结论徽章**
- 批准（通过色 + check-circle）、驳回（中性 + x-circle）、退回修改（预警色 + arrow-left）。

### 5.2 辅助信息

- 页头说明：批准、驳回、退回修改都会记录审批人、时间、结论和意见。

## 6. 交互流程

### 6.1 页面加载与初始化

- 审批者：默认"待我审批"，选中第一条并显示详情。
- 操作者：默认"已处理"，审批按钮与结论单选不显示。
- 只读：无权限。

### 6.2 核心操作流程

```
选一条待审批 → 看摘要 / 看全文
    ▼
选结论 + 填意见 → 提交审批结论
    ├─ 驳回 / 退回修改且意见为空 → 提示"驳回或退回修改时请填写意见"
    └─ 确认弹窗 → 确认提交
         ├─ 决策卡 · 批准 → 记录审批 → 卡片锁定只读版本 → 自动登记预测台账（PAGE-F26-01）→ 移到"已处理"
         ├─ 决策卡 · 驳回 → 卡片状态"已驳回"
         ├─ 决策卡 · 退回修改 → 卡片回到"草稿"
         ├─ 策略库 · 批准 → 条目改为"已验证"，生成新版本
         └─ 策略库 · 驳回 / 退回 → 条目状态不变
```

### 6.3 辅助操作

- 列表行支持回车选中。
- 已处理按审批时间排序。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 空 | 没有待审批 | "没有待你审批的内容。wen 提交决策卡或策略库申请后会出现在这里" |
| 加载 | 打开页面 | 列表骨架条 |
| 正常 | 有待审批 | 左列表 + 右详情 |
| 提交中 | 点确认提交 | 按钮不可重复点 |
| 提交失败 | 服务端异常 | 提示"提交失败，结论未保存，请重试"，表单内容保留 |
| 已被处理 | 打开时该条已被处理或撤回 | 提示"这条已处理"，刷新列表 |
| 无权限 | 只读角色 | 显示"无权限" |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 提交审批后 wen 又改了卡片 | 以提交审批时锁定的版本为准（PRD §5.2） |
| 批准后数据更新 | 快照不变，卡片提示"有新数据"（AC-F25-02，在 PAGE-F21-02 显示） |
| 重复提交 | 首次提交完成前禁用 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| 类型 | 决策卡立项 / 策略库改为已验证 |
| 结论 | 批准 / 驳回 / 退回修改 |
| 意见 | 文本 |
| 审批记录 | 审批人、时间、结论、意见、对象与版本 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 结论 | 提交 | 必选 | "请选择结论" |
| 意见 | 提交 | 驳回 / 退回修改时必填 | "驳回或退回修改时请填写意见" |

### 8.3 特殊业务规则

- **锁定（AC-F25-01）**：批准后该卡锁定为只读版本。
- **自动登记（AC-F25-03）**：决策卡批准即在预测台账登记该卡的预测。
- **已验证（AC-F25-05）**：策略库条目改为"已验证"必须经老板批准才生效。
- **备份**：每次审批后自动备份数据库（蓝图 §9）。
