## 2. 页面概述

### 2.1 一句话定位

把分框信号、条件表和经验结论放在一处，标明每条是"未验证经验 / 历史观察 / 已验证"，改动留版本，升为"已验证"必须老板批准。

### 2.2 存在理由

1. "评分做好就起量"这类经验和经过回测的信号混在一起，评审时分不清哪条能当依据。
2. 结论被改过多少次、为什么改，过去没有记录。
3. 谁都能口头说"这条已经验证了"，没有关口。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 状态清楚 | 100% 条目带三种状态之一 |
| 可追溯 | 每次修改都生成新版本，旧版本 100% 保留 |
| 关口 | 未经老板批准变为"已验证"的条目数为 0 |

### 2.4 不做什么（范围边界）

- **不自动根据回测改状态**：状态变化由人提交，"已验证"由老板批准。
- **不删除条目或版本**：需求只要求新增、修改与保留旧版本。
- **不在本页审批**：申请进入 PAGE-F25-01 审批。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 操作者：新增、修改、申请已验证；审批者：查看（在审批页批准）；只读：查看 |
| 人数 | 编辑 1 人，查看若干人 |
| 使用设备 | 办公电脑浏览器 |

### 3.2 核心使用场景

**场景 A：记下一条新经验（主场景）**
- 时机：评审会或复盘后。
- 动作：新增结论 → 填结论、类型、状态（未验证经验 / 历史观察）、依据 → 保存为 v1。

**场景 B：用新数据修改结论**
- 动作：打开条目 → "修改" → 改结论 / 依据 / 状态（不含已验证）并写修改说明 → 保存为新版本 → 版本历史可看前后差异。

**场景 C：申请改为已验证**
- 时机：回测或台账对账支持某条结论。
- 动作：点"申请已验证" → 填申请依据 → 提交 → 条目显示"申请已验证 · 待老板审批"，状态不变 → 老板在 PAGE-F25-01 批准后变为"已验证"并生成新版本。

### 3.3 用户核心诉求

1. **分得清**：一眼看出哪条能当立项依据。
2. **改得动**：新数据来了能改，但改动可追溯。
3. **有关口**：已验证必须老板点头。

## 4. 信息架构

### 4.1 区域划分

1. 页头（新增结论）
2. 状态统计（三种状态条数）
3. 筛选（状态、类型、搜索）
4. 条目列表 + 分页
5. 条目抽屉：当前版本 / 修改 / 版本历史
6. 弹窗：新增结论、申请改为已验证

### 4.2 区域内容

**条目列表**：编号、结论、类型（分框信号 / 条件表 / 经验）、状态、版本、依据、更新时间、操作（查看、申请已验证）；有待审批申请时在结论下显示"申请已验证 · 待老板审批"。

**条目抽屉**：
- 待审批横幅（有申请时）；
- 当前版本：状态、结论、适用框、依据、引用它的决策卡、版本号与修改人；
- 修改：结论、状态（未验证经验 / 历史观察）、依据、修改说明；
- 版本历史：每个版本的状态、修改人、时间、说明和前后差异。

**示例条目**（第一版浴室柜）：
- SL-06 只在同一框里比较 · 已验证 · v3；
- SL-01 分框信号：新品占比高于同框 · 历史观察（第九版回测中的经回测信号）· v3；
- SL-03 首月 ≥ 2 色、≥ 4 子体 · 历史观察 · v2 · 申请已验证待审批；
- SL-02 分框信号：份额近 6 个月比前 6 个月高 ≥ 2 个百分点 · 历史观察 · v2；
- SL-04 老板：评分做好就起量 · 未验证经验 · v1；
- SL-05 30″ 及以下从拆装切入比整装容易 · 未验证经验 · v1。

## 5. 界面内容

### 5.1 元素清单

**状态徽章**
- 已验证：通过色 + seal-check；历史观察：默认 + clock-counter-clockwise；未验证经验：预警色 + seal-question。

**新增结论（主按钮）**
- 显示条件：操作者。
- 弹窗字段：结论*、类型*、状态*（只有未验证经验 / 历史观察）、依据*。

**申请已验证**
- 显示条件：操作者；条目不是"已验证"且没有待审批申请。
- 有待审批申请时按钮不可用，提示"已有待审批申请"。
- 弹窗字段：申请依据*。

**保存为新版本**
- 显示条件：操作者，在"修改"中有改动。
- 结果：版本号 +1，旧版本进入版本历史。

### 5.2 辅助信息

- 页头说明：修改产生新版本，旧版本保留；改为"已验证"必须经老板批准。
- 未验证经验统计说明：只作参考，不进决策卡结论。

## 6. 交互流程

### 6.1 页面加载与初始化

- 显示全部条目，按更新时间倒序；状态统计按当前数据计算。

### 6.2 核心操作流程

```
新增结论 → 填写 → 保存为 v1 → 列表新增一行

查看条目 → 修改 → 保存为新版本（vN+1）→ 版本历史保留 vN

申请已验证 → 填依据 → 提交
    → 条目标"申请已验证 · 待老板审批"（状态不变）
    → PAGE-F25-01 审批
         ├─ 批准 → 状态"已验证"，生成新版本
         └─ 驳回 / 退回 → 状态不变，申请标记消失，审批意见可在审批页"已处理"查看
```

### 6.3 辅助操作

- 状态筛选单选，类型筛选可多选；搜索按结论文字。
- 修改未保存就关闭抽屉或离开页面时拦截。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 空 | 还没有条目 | "策略库还没有结论。记下评审会上的经验或回测发现" + 新增结论 |
| 加载 | 打开页面 | 列表骨架条 |
| 筛选无结果 | 筛选后为 0 | "没有符合条件的结论"，可清除筛选 |
| 待审批 | 条目有已验证申请 | 列表与抽屉显示待审批标记，申请按钮不可用 |
| 保存失败 | 服务端异常 | 提示"保存失败，修改未生效，请重试"，表单内容保留 |
| 只读 | 审批者、只读 | 无新增、修改、申请入口 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 修改已验证条目 | 允许修改结论与依据，生成新版本；状态只能保持已验证或改回历史观察 / 未验证经验 |
| 重复申请 | 已有待审批申请时不能再申请 |
| 修改时有待审批申请 | 审批针对申请时的版本 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| 编号 | 系统生成，如 SL-07 |
| 结论 | 文本 |
| 类型 | 分框信号 / 条件表 / 经验 |
| 状态 | 未验证经验 / 历史观察 / 已验证 |
| 依据 | 文本，写数据范围与样本量 |
| 版本 | v1 起，每次修改 +1；记录修改人、时间、修改说明 |
| 申请 | 申请人、时间、申请依据、审批结论 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 结论、依据 | 失焦 / 保存 | 不为空 | "请填写结论" / "请填写依据" |
| 修改说明 | 保存新版本 | 不为空 | "请写修改说明" |
| 状态 | 保存 | 直接保存只能选未验证经验 / 历史观察 | 选项中不出现"已验证" |

### 8.3 特殊业务规则

- **三种状态与版本（AC-F25-04）**：每条带三种状态之一；修改产生新版本，旧版本保留。
- **已验证需批准（AC-F25-05）**：任何人把状态改为"已验证"都必须经老板批准才生效。

## 9. 页面流转

### 9.1 流转图

```
策略库（本页）
   ├─申请已验证──→ PAGE-F25-01 审批 ──批准──→ 回到本页，状态"已验证"
   └─引用它的决策卡──→ PAGE-F21-02 决策卡详情
```

### 9.2 与其他模块的关系

- 关联：F25 审批；F21 决策卡引用条目状态。
- 隔离：状态变化不改已批准决策卡的快照。
