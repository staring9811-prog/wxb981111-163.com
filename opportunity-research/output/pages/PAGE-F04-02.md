## 2. 页面概述

### 2.1 一句话定位

把系统按"同品牌 + 同款式"提出的 SPU 合并建议交给 wen 核对：逐条或按依据批量确认，确认后才生效；已生效的归并可以拆分或修改，并留痕。

### 2.2 存在理由

1. **SPU 口径决定命中率的分子分母**：同一设计的不同尺寸、颜色常分成几个父 ASIN 上架。不合并，一个设计会被算成几个新品（REQ-F04-01、US-F04-01）。
2. **规则只能提建议**：标题、五点相似不等于同一设计，误合并会把老品算进新品。所以建议必须人工确认后才生效（AC-F04-02、AC-F04-03）。
3. **归并要可逆、可追溯**：发现合错了，要能拆开或改正，并知道改过什么、影响了哪些结果（AC-F04-05）。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 审核效率 | "标题主干相同"一类可筛出后一次批量确认；其余两类展开即可对照，不用离开本页 |
| 口径透明 | 每条建议都写明匹配依据；待审数与涉及的子 ASIN 数常驻可见 |
| 可追溯 | 每次确认、拒绝、拆分、修改都有操作人和时间；拆分和修改另记前后值 |

### 2.4 不做什么

- **不从零手工新建合并**：没有对应需求。只处理系统建议，以及对已生效归并的拆分和修改。
- **不删除**：拒绝只改变建议状态；第一期不提供删除业务数据的功能。
- **不自动重算**：确认、拆分、修改后只把受影响结果标为"需重算"，由 wen 在工作台重算（DEC-016）。
- **不在本页确认 SPU 编号字段**：编号字段在字段约定（PAGE-F02-01）中确认。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 产品经理 wen |
| 使用时机 | 首跑时审核历史批次的建议；每月导入后处理新建议（工作台第 4 步）；在成败明细里发现归并有误时 |
| 使用设备 | Windows，宽 1366–1920 |

### 3.2 核心使用场景

- **场景 A：月更审核（主场景）**
  - 动作：点"标题主干相同"→ 全选 → 批量确认 → 在弹窗确认；再逐条展开"高度相似"和"五点描述相同"两类，对照标题主干、类型属性和五点摘要后确认或拒绝。
  - 期望：不离开本页就能判断是不是同一设计。
- **场景 B：改正已生效的归并**
  - 时机：在 SPU 成败明细中发现两个父体不是同一设计。
  - 动作：切到"已生效归并"→ 找到该 SPU → 拆分或修改 → 确认弹窗 → 回工作台"全部重算"。
- **场景 C：数据包自带 SPU 编号**
  - 页面显示"已按编号归并，无需审核"，不出现待审建议。

## 4. 信息架构

### 4.1 区域划分

1. 页头：标题、口径说明、"新品与 SPU"按钮。
2. 计数条：待审、已确认、已拒绝、已按编号归并。
3. 标签：待审 / 已生效归并 / 已拒绝。
4. 待审面板：依据筛选与搜索、建议表（可展开对照）、批量操作条。
5. 已生效归并面板：确认方式筛选与搜索、归并表、分页、留痕说明。
6. 已拒绝面板：拒绝记录表、分页。
7. 弹窗：批量确认、修改归并、拆分归并。

### 4.2 区域内容

**页头**
- 标题"合并建议"。
- 副标题："同品牌、不同父 ASIN 之间按三条依据提出建议，确认后才生效 · 未确认前，涉及的子体按各自父 ASIN 分别计为 SPU"（AC-F04-03）。

**计数条**

| 计数 | 内容 |
| :--- | :--- |
| 待审 | 条数与涉及的子 ASIN 数，例："6 条 · 涉及 46 个子 ASIN" |
| 已确认 | 条数，以及逐条确认、批量确认各多少，例："214 条 · 逐条 63 · 批量 151" |
| 已拒绝 | 条数，例："37 条" |
| 已按编号归并 | 按数据包 SPU 编号归并的 SPU 数，这些不进入审核，例："128 个 SPU" |

**待审面板**
- 筛选：匹配依据（全部 / 标题主干相同 / 标题主干高度相似且类型属性一致 / 五点描述相同），每个标签带条数，悬停显示依据定义；搜索建议编号、品牌、ASIN。
- 建议表：

| 列 | 内容 |
| :--- | :--- |
| 勾选 | 表头全选只作用于当前筛选结果 |
| 建议 · 品牌 | 建议编号、品牌 |
| 涉及父 ASIN · 标题对照 | 每个父 ASIN 一行，并列其完整标题；已单独计为 SPU 的父体注明"现为 SPU-2611-019（暂按父体）" |
| 子 ASIN | 涉及的子 ASIN 总数 |
| 匹配依据 | 三条之一；高度相似写出相似度，例"标题主干高度相似（0.93）且类型属性一致" |
| 操作 | 确认、拒绝 |

- 行下方"对照 n 个父体"可展开：以父 ASIN 为列，逐行对照尺寸与子体数、标题主干、形态、安装方式、台面形态、元素、五点摘要。各父体取值相同时合并成一格；最后一列写对照结论："相同""一致""相似度 0.93""措辞不同""无法比较（信息不足）"。
- 批量操作条：勾选后出现，显示"已选 n 条建议"、"取消选择"、"批量确认"。
- 面板底部提示："建议先按依据筛出'标题主干相同'批量确认，再逐条核对其余两类。确认或拒绝都会记录操作人与时间。"

**已生效归并面板**

| 列 | 内容 |
| :--- | :--- |
| SPU · 品牌 | SPU 编号（进入成败明细）、品牌 |
| 涉及父 ASIN | 当前归并包含的父 ASIN |
| 子 ASIN | 当前子 ASIN 数 |
| 来源建议 | 建议编号与匹配依据 |
| 确认 | 逐条确认 / 批量确认、操作人、时间 |
| 修改记录 | "未修改"，或"修改 n 次 · 最近日期"，展开看每次修改前后的父 ASIN 与子 ASIN 数、操作人、时间、受影响结果的重算时间 |
| 操作 | 修改、拆分（拆分为危险操作） |

- 筛选：确认方式（全部 / 逐条确认 / 批量确认）、有修改记录；搜索 SPU 编号、品牌、ASIN。
- 分页：每页 50 条，例"第 1–6 条，共 214 条"。
- 底部说明："拆分或修改会记录修改前后、操作人和时间，并把受影响的成败判定、信号和回测标为需重算；系统不自动重算，旧结果在重算前仍可查看。"

**已拒绝面板**
- 说明："被拒绝的建议不生效，涉及的子体继续按各自父 ASIN 计为 SPU。"
- 表格：建议编号与品牌、涉及父 ASIN、子 ASIN 数、匹配依据、拒绝人与时间；分页。

## 6. 交互流程

### 6.1 加载与初始化

- 默认打开"待审"，依据为"全部"，第一条建议的对照默认展开。
- 没有待审建议时，"待审"显示空状态（见 7.1），计数照常显示。

### 6.2 核心操作流程

```
进入合并建议
  ├─ 待审
  │   ├─ 点依据标签 → 只显示该依据的建议（全选也只作用于这些）
  │   ├─ 展开"对照 n 个父体" → 逐项对照标题主干、类型属性、五点摘要
  │   ├─ 点"确认" → 建议生效，移到"已生效归并"（来源：逐条确认）→ 受影响结果标需重算
  │   ├─ 点"拒绝" → 移到"已拒绝"，子体继续按各自父 ASIN 计
  │   └─ 勾选 → 批量操作条 → "批量确认" → 确认弹窗 → 一次确认所选（来源：批量确认）→ 标需重算
  ├─ 已生效归并
  │   ├─ "修改" → 弹窗：移出或加入父 ASIN → 保存 → 记录前后值、操作人、时间 → 标需重算
  │   ├─ "拆分" → 弹窗：确认拆分 → 各父 ASIN 单独计为 SPU → 记录 → 标需重算
  │   └─ 点 SPU 编号 → PAGE-F05-01 SPU 成败明细
  └─ 已拒绝：只读查看
处理后：工作台第 4 步与待处理区同步更新；需重算横幅出现在工作台和受影响的结果页
```

### 6.3 辅助操作

- 弹窗按 Esc、点遮罩或"取消"关闭，不做任何改动。
- 展开的对照、勾选状态在切换依据筛选时保留在各自行上。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 已按编号归并（空态） | 数据包提供 SPU 编号字段，且该字段已在字段约定中确认（AC-F04-01） | 计数条下方显示空状态："已按编号归并，无需审核。数据包 P-xxxx 提供了 SPU 编号，系统按编号把子体归并为 SPU。"按钮"查看新品与 SPU"；"已生效归并""已拒绝"仍可查看以前的记录 |
| 部分子体有编号 | 只有部分子体带已确认的 SPU 编号 | 带编号的按编号归并，计入"已按编号归并"；其余子体照常生成建议 |
| 编号字段未确认 | 数据包有 SPU 编号，但字段约定中尚未确认 | 按"未提供已确认编号"处理，照常生成建议（AC-F04-02）；页头提示"SPU 编号字段尚未确认"，链接到 PAGE-F02-01 |
| 正常 | 有待审建议 | 默认显示待审 |
| 没有待审 | 建议都已处理 | 待审面板显示"没有待审的合并建议"，计数为 0 |
| 筛选无结果 | 当前依据下没有建议 | 表格区显示"没有符合条件的建议"，提供"清除筛选" |
| 已改动归并 | 确认、拆分或修改之后 | 轻提示；受影响的成败、信号、回测页面显示需重算横幅，旧结果仍可查看（DEC-016） |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 未确认的建议 | 不参与成败判定和回测，涉及的子体按各自父 ASIN 分别计为 SPU（AC-F04-03）；PAGE-F04-01 页头提示待审条数 |
| 合并改变上架日 | 合并后 SPU 上架日取全部子体上架日的最早值，晚于它上架的子体改标新变体，SPU 可能换批次；这些变化在重算后体现 |
| 一类属性信息不足 | 对照中写"信息不足"，结论列写"无法比较"；不影响"标题主干相同""五点描述相同"两类依据本身 |
| 重复确认 | 已处理的建议不再出现在待审中；批量确认只处理勾选时仍为待审的建议 |
| 拆分 | 不删除任何数据；拆分后可通过"修改 → 加入父 ASIN"再次合并，每次都留痕 |

## 8. 业务规则

- **适用条件**：只在同品牌、不同父 ASIN 之间提建议，每条建议注明依据（DEC-009）。
- **三条依据**（DEC-009）：
  1. 标题主干相同：去掉尺寸、颜色、数字和通用词之后，标题完全相同。
  2. 标题主干高度相似且类型属性一致：标题主干相似度 ≥ 0.9，且形态、安装方式、台面形态、元素全部一致。
  3. 五点描述相同：五点描述去掉格式后完全相同。
- **生效**：建议只有确认后才生效；确认来源记为"逐条确认"或"批量确认"（AC-F04-04）。
- **有编号**：数据包提供 SPU 编号且该字段已确认时，直接按编号归并，不生成建议（AC-F04-01）。
- **修改留痕**：拆分或修改记录修改前后（父 ASIN、子 ASIN 数）、操作人、时间（AC-F04-05）。
- **需重算**：确认、拆分、修改后，受影响的成败判定、信号和回测标为"需重算"，不自动重算（AC-F04-05、DEC-016）。

## 11. 验收标准

### 11.1 功能验收
