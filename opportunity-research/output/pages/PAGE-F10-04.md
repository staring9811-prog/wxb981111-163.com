## 2. 页面概述

### 2.1 一句话定位

记下每个立项决定和当时的快照、理由，日后与结果对照；记录不可改，录错只追加更正。

### 2.2 存在理由

1. **积累自家结果**：判定卡在真实决策中是否有效，要靠一条条带快照的决定来检验（US-F10-01、AC-F10-02）。
2. **系统启用前已有在研项目**：要补录，才能纳入日后的自家对账（AC-F10-03）。
3. **台账要经得起对账**：事后改记录会让对账失去意义，所以只追加更正（DEC-007）。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 记录完整 | 每条记录都有决定、关联细分、来源、操作人与时间；"记录"类都带对应快照 |
| 更正可追溯 | 被更正的记录与更正记录互相链接，原记录完整保留 |
| 对账可达 | 每个立项一次点击进入上架数据录入，结果回显在状态列 |

### 2.4 不做什么

- **不编辑、不删除记录**：DEC-007；第一期没有删除业务数据的功能。
- **不在本页判定成败**：自家上架数据在 PAGE-F10-06 录入并即时判定，汇总在 PAGE-F10-05。
- **不维护项目进度**：状态只显示可推导的"在研"（无上架日期）或"已上架"（有上架日期）（DEC-028）。

## 3. 用户与场景

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 产品经理 wen |
| 使用时机 | 立项评审后；首跑补录；自家产品上架后每月 |
| 使用设备 | Windows，宽 1366–1920 |

- **场景 A：记录决定**：立项评审后，在本月排序行上点"记录立项决定"，或在本页点"记录决定"，记下立项或不立项与理由（如 D-0006：不立项，锦囊为放弃）。
- **场景 B：补录在研立项**：首跑时把系统启用前已在研的立项补进来（D-0001、D-0002）。
- **场景 C：更正**：发现 D-0003 的关联细分误填为悬浮式，点"更正"追加 D-0004，D-0003 标"已更正"。
- **场景 D：录入上架数据**：自家产品上架后，每月补录月度数据，看自家对账结果（D-0001 未命中）。

## 4. 信息架构

### 4.1 区域划分

1. 页头：标题"台账"、副标题；操作"从数据包导入自家立项""补录在研立项""记录决定"（主按钮）。
2. 台账标签：月度快照 / 立项记录（当前）/ 到期对账。
3. 不可修改横幅（常驻）。
4. 筛选：决定、来源；"列"。

**不可修改横幅**：立项记录保存后不可修改。录错时追加一条更正记录，原记录标"已更正"并保留，两条记录互相链接；操作人和时间在保存时自动记录。

**记录表**（新的在上，每页 50 行）

| 列 | 内容 | 次要列 |

## 6. 交互流程

### 6.1 加载与初始化

- 默认显示全部记录，新的在上；筛选为"全部"。
- 读取当前数据包是否含 C7，决定导入按钮是否可用。

### 6.2 核心操作流程

```
进入立项记录
  ├─ 点"记录决定" → PAGE-F10-02（记录决定）→ 保存 → 回到本页，顶部新增一条（来源"记录"）
  ├─ 点"补录在研立项" → PAGE-F10-02（补录）→ 保存 → 新增一条（来源"补录"）
  ├─ 点"从数据包导入自家立项" → 读取 C7
  │    ├─ 都已在台账中 → 轻提示"已读取 P-0008 的 C7 自家立项 4 行：都已在台账中，没有新的立项或上架数据"
  │    └─ 有新内容 → 确认弹窗列出将新增的补录记录和上架数据 → 确认后写入，来源记为"补录"，上架数据注明来自 C7
  ├─ 点某行"更正" → PAGE-F10-02（带入原记录，注明"更正 D-xxxx"）→ 保存
  │    → 新增一条来源"更正"的记录；原记录标"已更正"，两条互链
  ├─ 点"录入上架数据" → PAGE-F10-06 → 保存后即时判定 → 状态列更新
  └─ 点对应快照 / 看对账 → PAGE-F10-01 / PAGE-F10-05
```

### 6.3 辅助操作

- 点"更正 D-0003""见更正记录 D-0004"在表内跳到对应行。
- "列"：窄屏下调出"记录时间与操作人"。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 空 | 还没有立项记录 | 空状态："还没有立项记录。立项评审后记录决定，或补录系统启用前已在研的立项。"按钮"记录决定""补录在研立项" |
| 正常 | 有记录 | 横幅、筛选、记录表 |
| 无 C7 | 当前数据包没有 C7 | 导入按钮禁用，悬停说明原因 |
| 读取中 | 正在读取 C7 | 导入按钮显示"读取中…"，不可重复点击 |
| 筛选无结果 | 当前筛选下没有记录 | "没有符合条件的立项记录"，提供"清除筛选" |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 更正记录再更正 | 允许；新的更正记录链接到上一条，链路按时间串起 |
| 被更正的记录 | 不再提供"录入上架数据"和"更正"；自家对账以最新的更正记录为准 |
| 补录记录 | 没有对应快照；自家对账时"当时的排序与锦囊"显示"无对应快照"和当时依据 |
| C7 与已有记录重复 | 按立项名称和立项日期匹配，已存在的不重复新增 |
| 不立项的决定 | 不参与自家对账，不提供"录入上架数据" |

## 8. 业务规则与校验

- **记录决定的字段**（AC-F10-02）：决定、关联细分、理由（必填）、对应快照（保存时最新的快照，月份 + 版本）、操作人、时间；决定为立项时另记立项日期，立项名称选填。
- **补录的字段**（AC-F10-03）：立项名称、立项日期、关联细分必填，当时依据选填；记录标"补录"，没有对应快照。
- **不可修改**（DEC-007）：保存后不可修改、不可删除。更正 = 新增一条来源为"更正"的记录，原记录标"已更正"，两条互链。
- **编号**：按保存顺序从 D-0001 递增，不复用。
- **C7 导入**（DEC-012）：当前数据包含 C7 时可用；新立项按"补录"写入，上架后月度数据写入对应立项的上架数据。
- **自家对账结果**：由上架数据按品类配置的成功线判定（AC-F10-05），规则见 PAGE-F10-06。
- **状态来源**：有上架日期（来自"录入上架数据"或 C7）即为已上架，否则为在研；需求未定义项目阶段，不另设字段（DEC-028）。

## 9. 页面流转

```
台账标签 ──→ 立项记录（本页）
               ├─ 记录决定 / 补录在研立项 / 更正 ──→ PAGE-F10-02 ──保存──→ 本页
               ├─ 录入上架数据 ──→ PAGE-F10-06 ──保存──→ 本页
               ├─ 对应快照 ──→ PAGE-F10-01
               └─ 看对账 ──→ PAGE-F10-05
```

**扩展预案**：第二期多人使用时，记录已带操作人；只读角色隐藏三个页头操作和行操作。
