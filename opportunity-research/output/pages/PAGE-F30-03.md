## 2. 页面概述

### 2.1 一句话定位

把 wen 本机抓好的小平台数据安全地导入：先挡住格式和口径问题，再让 wen 看清楚会改变什么，确认后才生效。

### 2.2 存在理由

1. 本期系统不抓取，数据靠本机脚本产出，列名、渠道值、月份、重复都可能出错（AC-F30-01～04）。
2. 同一渠道同月已有评论 VP 并入数据，两边对不上要让 wen 判断（AC-F30-06）。
3. 导入替换整渠道数据，必须留版本、可回看（AC-F30-07）。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 响应 | 上传到显示核对摘要 ≤ 60 秒（NFR-014） |
| 安全 | 任何检查失败或未确认，已生效数据 0 改动；导入后机会扫描等数字 0 变化（AC-F30-08） |

### 2.4 不做什么

- **不做**系统内抓取（第二版）。
- **不做**写入其他渠道分析库（F28）。
- **不做**逐行编辑导入数据——有错改本机文件后重传。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 只有操作者；审批者、只读在侧栏看不到此页，直接访问提示"无权限"（AC-F30-09） |
| 使用时机 | wen 本机跑完 `大词抓取_三平台整理.py 整理` 后，约每月一次 |

### 3.2 核心使用场景

**场景 A：正常导入 Home Depot + Wayfair（主场景）**
- 动作：拖入 `三平台_商品表.csv`、`三平台_月销表.csv` → "开始检查"。
- 结果：检查通过；核对摘要按渠道列出：Home Depot 218 个家族、2026-01 至 10、窗口销量 206,750、有月度 100%、已落框 99.3%、分框待确认 36；Wayfair 633 个商品、窗口销量 333,580（另估算 219,130，低估计 90,950）、有月度 60%、已落框 88.1%、待确认 83；11 月 412 行"只作参考"。
- 冲突：Wayfair 2026-03 类目节点评论 812 条 vs 已并入 760 条（+6.8%）→ 标"与已有数据不一致"，wen 勾选"确认导入 Wayfair"→ "确认导入"。

**场景 B：缺列被拒**
- 表现：商品表缺"装"列 → 红色结果"未导入：商品表缺少列 装"，已生效数据不变。

**场景 C：Lowe's 导入后数据不足**
- 表现：摘要里 Lowe's 已落框 1.1%，提示"导入后该渠道将显示'数据不足'"；仍可确认导入。

## 4. 信息架构

### 4.1 区域划分

1. 页头（面包屑 工作台 / 数据 / 渠道调研导入；说明"不进入机会扫描与模型"）
2. 步骤条：① 上传 → ② 检查 → ③ 核对摘要 → ④ 确认
3. 上传区：两个拖放框（商品表、月销表，CSV）+ 必需列说明折叠
4. 检查结果：通过 / 未通过；未通过时按问题类型列表（缺列、渠道值、重复、对不上、月份格式、数值），每类行数 + 前 20 条示例
5. 核对摘要（按渠道一张卡）：商品数、家族数、完整月范围、窗口销量合计（含估算单列）、有月度销量占比、已落框销量占比、分框待确认数、只作参考行数、与当前版本的变化；冲突时内嵌逐月对照表（月份、导入条数、已并入去重条数、差异%）与"确认导入该渠道"勾选
6. 底部操作：放弃 / 确认导入（未勾选的冲突渠道不导入，按钮文案写明将导入哪些渠道）
7. 导入记录：版本、渠道、导入时间、文件名、商品数、月份范围、操作人、状态（当前 / 已替换 / 已放弃）

### 4.2 必需列

- 商品表：渠道、fam、pid、title、来源、尺寸段、装、形态、台面材质、主色、柜体材质、元素、价格、评分、页面评论数；可选：首评月。
- 月销表：渠道、fam、pid、尺寸段、装、形态、月、VP、非VP、销量。

## 6. 交互流程

1. 选两个文件 → "开始检查"（按钮在两个文件都选好后可用）→ 进度。
2. 未通过：显示问题，可"重新选择文件"。
3. 通过：显示核对摘要；有冲突的渠道默认不勾选。
4. "确认导入"→ 确认弹窗（列出将导入的渠道、将替换的版本、分框待确认数）→ 确认 → Toast"已导入 Home Depot、Wayfair；分框待确认 119 个已进打标确认"→ 跳 PAGE-F30-01。
5. "放弃"→ 本次核对作废，记录"已放弃"。
6. 核对摘要未确认时又上传：后一次替换前一次（RA-129）。
