## 2. 页面概述

### 2.1 一句话定位

一张表看清所有决策卡走到哪一步，点进去看或审。

### 2.2 存在理由

1. 卡片跨越草稿、审批、跟踪、对账多个阶段，需要一处总览。
2. 评审会需要快速找到某个框、某个状态的卡。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 找到 | 按状态、分框、关键字两步内定位 |
| 新建 | 新建一律从机会扫描进入，保证卡片有单元来源 |

### 2.4 不做什么

- **不做**在列表里直接新建空白卡——卡片必须以扫描单元为目标（AC-F20-05）。
- **不做**列表内审批——在 PAGE-F21-02 或 PAGE-F25-01 审批。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 全部角色可看；"去机会扫描新建"仅操作者显示 |

### 3.2 核心使用场景

- **场景 A**：wen 查看待审批和草稿的卡，点进详情继续编辑。
- **场景 B**：老板筛"待审批"，点进详情审批。
- **场景 C**：切到 Home Depot 主渠道，看到空状态并去机会扫描。

## 4. 信息架构

### 4.1 区域划分

1. 顶栏（渠道切换：按主渠道筛）
2. 页头（标题、说明、导出、去机会扫描新建）
3. 筛选（状态带计数、分框、搜索）
4. 列表 + 分页
5. 页脚状态流转说明

### 4.2 区域内容

- **列表列**：决策卡（属性取值 + 副行：机会类型、版本、补充状态如"有新数据"、驳回意见摘要）、主渠道、分框、状态、更新时间、进入箭头。
- **示例 4 张**（主渠道均为 Amazon）：

| 决策卡 | 分框 | 状态 | 更新时间 |
| :--- | :--- | :--- | :--- |
| 台面材质：树脂一体 | 30″ · 拆装 · 落地式 | 待审批 | 2026-11-03 10:42 |
| 元素 × 台面材质：竖棱 × 树脂一体 | 60″ · 拆装 · 落地式 | 草稿 | 2026-11-02 17:30 |

## 5. 界面内容

### 5.1 元素清单

**状态徽章**：草稿 / 待审批 / 已批准 / 已驳回 / 跟踪中 / 已对账，每个带图标与文字。

**状态筛选**：全部 + 六种状态，各带计数（计数为 0 也显示）。

**分框筛选**：列出现有卡涉及的框。

**搜索**：按卡名、属性取值过滤。

**去机会扫描新建（主按钮）**：跳 PAGE-F20-01；仅操作者。

## 6. 交互流程

```
进入 → 默认主渠道 Amazon、全部状态，按更新时间倒序
  ├─ 点行 / 卡名 → PAGE-F21-02
  ├─ 切主渠道 → 无卡时空状态 + "去机会扫描"
  └─ 去机会扫描新建 → PAGE-F20-01 → 做决策卡 → PAGE-F21-02（草稿）
```

- 表头"更新时间"可排序；导出 Excel；每页 50 条。

## 7. 状态与边界

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 正常 | 有卡 | 列表 |
| 空 | 该主渠道没有卡 | 空状态说明 + 去机会扫描 |
| 筛选为空 | 无匹配 | 列表为空并显示 0 张 |
| 加载 | 首次 | 骨架条 |

| 边界场景 | 处理策略 |
| :--- | :--- |
| 已批准卡依据的数据更新 | 副行显示"有新数据"（AC-F25-02） |
| 已删除的卡 | 软删，不在列表显示（蓝图 §9） |

## 8. 业务规则与校验

- 状态流转：草稿 → 待审批 → 已批准 / 已驳回 / 退回修改（回到草稿）；已批准 → 跟踪中（台账上架后）→ 已对账（PRD §4.2）。
- 主渠道 = 创建卡时机会扫描所在渠道。

## 9. 页面流转

```
左侧栏 → 本页 → PAGE-F21-02 决策卡详情
          └─ 新建 → PAGE-F20-01 机会扫描 → 做决策卡 → PAGE-F21-02
```

## 11. 验收标准

| 编号 | 验收点 | 通过标准 |
