# 方案 V1 · 品类机会判定台

> 输入：`scene-anchor.md`（用户已确认）、`output/解题方案书.md`（用户已确认）、`state.json` 决定 D-1 至 D-21。V0 → V1 的修订见 `debate-log.md`。

## 1. 解决思路

在 wen 的电脑上做一个本机小网页。wen 把按《数据接口约定》准备好的数据包导入，系统用固定代码完成"校验 → 确认字段约定 → 体检 → 判新品、归并 SPU → 判 6 个月成败 → 算信号 → 回测 → 判定卡与锦囊 → 排序 → 台账 → 策略库 → 导出报告"。所有计算由代码完成，同样输入得到同样结果；大模型步骤（打标、评论痛点提取）不在本系统内，由数据侧完成后随数据包导入。

## 2. 主流程（谁提供什么 → 系统怎么处理 → 谁得到什么）

| 步骤 | 输入 | 系统处理 | 产出 |
|---|---|---|---|
| 导入 | wen 拖入数据包（约定内的 Excel/CSV/JSON） | 按约定校验必需文件、字段、类型、主键唯一、月份覆盖、口径标记 | 校验报告：通过 / 警告 / 阻断（阻断时不进入计算） |
| 字段约定确认 | 导入的字段 | 逐字段列出含义、粒度（子体/父体/SPU）、时点（当月值/快照）、性质（实测/估算/推导）、建议用法（✅直接用/⚙️按规则用/⛔回测不用）及体检证据 | wen 逐项确认或修改，形成"字段约定 vN"；未确认字段不参与计算 |
| 自动体检 | 已确认约定 + 数据 | 固定检查：首评早于上架比例、家族内上架日跨度、购买标签越界、关键维度未知占比、父体迁移、重复记录等 | 异常清单（只提示、不改数据） |
| 新品与 SPU | 商品与标签 | SPU 归并：优先用数据包里的 SPU 编号；没有时按"同品牌 + 同款式"规则给出合并建议和依据，进入待审清单，wen 确认或拆分后才生效。SPU 上架日 = 子体最早上架日，并与首评日期交叉核验；老家族新增子体标"新变体"；疑似重新上架单独标记 | 新 SPU 清单与月度批次 |
| 成败判定 | 新 SPU 的月度轨迹 | 上架后 6 个月内：小类 BSR 前 50（ASIN 层，取法按约定）或 SPU 任一月销售额 ≥ $10 万（D-24、D-25 更正）（子体月销售额累加，不用当前快照价格），满足其一即命中；不满 6 个月标"观察中" | 每个新 SPU 的成败与依据 |
| 信号 | 按品类配置的细分（宽度档、形态、材质、风格、价格带等，分档可调） | 一律只用批次上架月之前可见的数据（评论按评论日期截断，关键词只用此前月份，标为"快照"的字段不进入回测）。父体回填的属性带标记，每个细分显示回填占比。每个细分每月：需求在涨（关键词同比动量，按映射规则对应到细分）；新品进得去（此前批次新品命中率）；现有产品没做好（上架当月之前的评论痛点 × 高销低评）；另把产品经理现用指标（单位 ASIN 贡献、属性溢价、属性趋势、低分高销）作为候选信号 | 细分 × 月份信号表 |
| 回测 | 信号表 + 成败 | 按时间切分（默认前 8 批定规则、后 4 批检验），控制可观察干扰因素（卖家/品牌实力、上架月份、价格定位、变体数、配送方式、疑似重新上架）；对照"全类目平均命中率的 2 倍"和"任一单指标排序"两条基线；新 SPU 少于 20 的细分标"样本不足"，不参与 2 倍评估，并提示改粗分档 | 回测报告：达标 / 未达标、提升倍数、样本量、区间、未达标原因（数据 / 细分 / 信号） |
| 判定卡与锦囊 | 回测结果 | 达标时生成判定卡 vN（指标、阈值、权重）与锦囊（条件 → 立项候选 / 观察 / 放弃，预期命中率区间、依据批次、n、状态）；未达标时判定卡标"未验证"，结论不可用于立项 | 判定卡、锦囊 |
| 排序 | 当月信号 + 判定卡 | 对当前全部细分排序，附区间与对应锦囊 | 当月细分排序 |
| 台账 | 当月排序 + wen 的立项决定 | 每月自动存快照；wen 记录立项决定（立项/不立项、理由、关联细分，可补录在研立项）；到 6 个月自动对账竞品新品实际命中率，自家立项结果手动补录 | 台账与对账结果 |
| 策略库 | 判定卡、锦囊、经验规则 | 规则带版本，状态分未验证经验 / 历史观察 / 已验证；wen 可新增经验规则并说明理由，修改保留历史 | 当前规则与历史版本 |
| 导出 | 上述结果 | 生成 Excel 与单文件网页报告（离线可打开，不依赖本系统） | 发给老板和开发、采购、运营 |

## 3. 交付物清单（第一期）

1. 本机小网页（Windows，一键启动，仅本机访问）。
2. 《数据接口约定 v1》：写在 PRD 附录，供 wen 准备数据、供后续数据项目按此输出。
3. 品类配置：亚马逊美国 · 浴室柜（小类节点 6810202011）。
4. 备份与恢复：每次月度更新后自动把台账、策略库、字段约定与确认记录备份到 wen 指定的目录，可一键恢复。
5. 用时记录：按步骤记录系统内用时，汇总"首跑"与"月更"两项（D-20）。

## 5. 角色与操作面

- 第一期：产品经理（wen）是唯一操作者，使用本机小网页全部功能；老板和开发、采购、运营不登录系统，只接收导出的报告。
- 第二期起：多人登录与权限（不在本次交付）。第一期的记录都带操作人与时间，业务计算与网页分离，迁服务器时不重做业务逻辑。

## 9. MVP 划分（已与企业家确认）

- **本次交付范围 = 第一期**（D-8，用户选择"分三期，先做透浴室柜"）：亚马逊美国 · 浴室柜，§4 全部 F01–F14，本机小网页（D-16），不含数据拉取（D-19）、大模型调用（D-18）、多人与权限（D-17）。
- **后续阶段**：第二期——迁服务器、多人与权限、接第二个品类；第三期——接 HDP、Lowe's、Wayfair。
- **端、渠道与接口**：只有本机网页一个操作端；数据入口只有"导入符合约定 v1 的数据包"；对外输出只有 Excel 与单文件网页报告。
- **方案前置能力**：见 §6；第一期数据包交付时间待用户确认。
- **可观察的完成定义**：
  1. 用符合约定的浴室柜数据包，能在本机小网页上从导入一路跑到：校验报告、字段约定确认、体检异常清单、新 SPU 与成败、细分信号、回测报告（达标或未达标及原因）、判定卡与锦囊（未达标时标"未验证"）、当月排序、台账快照、Excel 与网页报告导出；
  2. 同一数据包与同一约定版本运行两次，结果完全一致；
  3. 备份后可恢复出相同的台账、策略库和确认记录；
  4. 系统内用时被记录，可汇总"首跑"与"月更"。
- **不属于软件完成定义**：回测是否达到 2 倍是对方法的业务验证结果（方案书 §6），系统只负责如实算出并展示。
