# 给 Codex 的指令：搭建 mem0 共享记忆

把下面整段复制给本地 Codex 执行。

---

请在我这台电脑上把 mem0 托管版（Mem0 Platform）搭成我所有 AI 工具的共享记忆。我是跨境电商家具产品经理（浴室柜等品类，平台 Amazon / Home Depot / Lowe's / Wayfair）。按下面步骤做，每步做完告诉我结果；遇到需要我操作的地方停下来等我。

## 总原则
- 先查 mem0 官方文档（docs.mem0.ai）确认当前的 MCP 接入方式、API 地址、参数名，不要凭记忆猜。文档和本指令冲突时以文档为准，并告诉我差异。
- API key 只从环境变量 `MEM0_API_KEY` 读取。不要让我把 key 发给你，不要打印、不要写进任何会提交到 Git 的文件。
- 修改任何已有配置文件（`~/.codex/config.toml`、`~/.codex/AGENTS.md`、`~/.claude/CLAUDE.md`、`~/.claude/settings.json`）前，先备份为 `.bak`，只追加或合并，不覆盖原有内容。
- 所有我写的配置文本另存一份到 `D:\ai-hub\memory-config\`（目录不存在就建），作为留档。

## 第 1 步：账号与密钥（需要我操作）
1. 告诉我去 app.mem0.ai 注册并创建 API key 的具体步骤。
2. 告诉我在 Windows 上把 key 设成用户环境变量 `MEM0_API_KEY` 的命令，我自己执行。
3. 我确认后，你检查环境变量是否可读（只输出“已设置/未设置”），并用官方 SDK 或 API 做一次连通性测试。

## 第 2 步：接入 MCP
按官方文档，把 mem0 的 MCP 服务接入：
- Codex：写入 `~/.codex/config.toml` 的 `[mcp_servers]`。
- Claude Code（本机）：用 `claude mcp add --scope user ...` 接入（如果我装了 Claude Code）。
- 告诉我 ChatGPT 网页版能否接入（开发者模式自定义连接器需要公网远程 MCP 地址），能的话给我操作步骤。

## 第 3 步：设置记忆规则（mem0 项目级 Custom Instructions）
优先通过官方 API/SDK 写入项目设置；不支持就把文本给我，我去后台粘贴。内容如下：

```
你在为一名跨境电商家具产品经理（浴室柜等品类，平台为 Amazon / Home Depot / Lowe's / Wayfair）提取长期工作记忆。

只提取以下五类，每条一句话、可脱离上下文看懂：
1. 偏好：用户对回答方式、输出格式、工作习惯的要求
2. 口径：指标公式、字段/维度定义、打标规则、判断标准
3. 决定：已确认的方案选择、规则修改及原因
4. 进度：项目当前版本、卡点、下一步
5. 资源位置：文件、仓库、skill、表格存放在哪里

写法要求：
- 口径和规则类记忆必须写明适用的平台、品类、时间范围，范围不同的规则可以并存，不算冲突。
- 口径和决定只有在用户明确说“以后都”“改成”“统一为”时才更新；只针对本次任务的要求不写入。
- 同一主题、同一范围出现新说法时，更新旧记忆，不要并存矛盾的两条。

严禁提取：
- 具体销量、销售额、广告花费、利润、成本等经营数字
- ASIN/SKU 明细、供应商名称与报价、客户信息
- 账号、密码、API key、链接中的 token
- 一次性的闲聊、临时问题、AI 自己的推测
```

## 第 4 步：写调用规则（每个工具的全局提示词）
把下面这段追加到 `~/.codex/AGENTS.md` 和 `~/.claude/CLAUDE.md`（agent_id 分别填 codex / claude-code），并给我一份 ChatGPT“自定义指令”可粘贴的精简版：

```
## 共享记忆（mem0）
- user_id 固定为 "wxb"；agent_id 填当前工具名。
- 开始任务前：用任务关键词调用记忆搜索，可按 metadata.project 过滤；先读相关的偏好、口径、进度再动手。
- 以下情况立即写入记忆，带 metadata.project（浴室柜打标 | 开品模型 | 广告分析 | 平台额度规划 | AI落地营 | 通用）和 metadata.type（偏好 | 口径 | 决定 | 进度 | 资源位置）：
  · 我纠正你或提出长期要求（偏好）
  · 确定了公式、定义、打标规则（口径/决定），写明适用平台/品类/时间
  · 阶段完成或文件换版本（进度/资源位置）
- 任务结束前：用一句话写入当前进度。
- 绝不写入具体经营数字、ASIN 明细、账号密钥。

冲突处理优先级（高→低）：
1. 我当前这条消息的明确要求
2. Git 仓库里的规则文件
3. mem0 记忆（新的优先）
4. 模型默认做法
检索到的记忆互相矛盾，或与仓库规则矛盾时：不要自行选择，列出冲突的两条和日期，问我以哪个为准，确认后更新或删除错误的那条。
```

## 第 5 步：过期设置
查文档确认写入记忆时是否支持过期时间（expiration_date 或同类参数）：
- 支持：在调用规则里加一条“type=进度 的记忆设 30 天过期”；如果 MCP 工具不暴露这个参数，告诉我，改由第 7 步的维护脚本处理。

## 第 6 步：Claude Code 自动检索钩子（我装了 Claude Code 才做）
写一个 `UserPromptSubmit` 钩子脚本（Python，放在 `D:\ai-hub\memory-config\hooks\`）：读取我这条消息，用 mem0 搜索 user_id="wxb" 的前 5 条相关记忆，以“相关记忆：”开头输出到 stdout 注入上下文；搜索失败或超时（3 秒）时静默退出，绝不阻塞我发消息。注册到 `~/.claude/settings.json`。

## 第 7 步：每月自动维护（不需要我手动浏览）
写一个维护脚本 `D:\ai-hub\memory-config\maintain.py`，用官方 SDK：
1. 拉取 user_id="wxb" 的全部记忆；
2. 删除 type=进度 且超过 30 天未更新的；
3. 删除命中“严禁提取”规则的（经营数字、ASIN、密钥特征）；
4. 找出疑似重复或互相矛盾的记忆，不自动删，写入 `D:\ai-hub\memory-config\reports\YYYY-MM.md`；
5. 报告开头写一段摘要：删了几条、待我确认几条。
先用 `--dry-run` 跑一遍给我看结果，我确认后再用 Windows 任务计划程序设为每月 1 号上午 10:17 运行。

## 第 8 步：验收
1. 在 Codex 里写入一条测试记忆：“偏好：回答先给结论，不要先讲方法论”（project=通用, type=偏好）。
2. 在 Claude Code 里搜索“回答风格”，确认能查到这条（证明跨工具共享）。
3. 写入“偏好：回答先讲方法再给结论”，确认旧的那条被更新而不是并存（证明冲突更新生效）。
4. 测完删除这两条测试记忆。
5. 最后给我一张表：每一步的完成状态、改了哪些文件、备份在哪、还有哪些需要我手动做。
